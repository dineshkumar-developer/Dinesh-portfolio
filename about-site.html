Technical Overview

How This Portfolio Is Built

This page documents the current merged portfolio: one shared content structure, two selectable themes, theme-specific CSS, theme-specific runtime controllers, responsive navigation, and the cleanup choices that keep the site maintainable after combining the original projects.

Project Model

Static Site With No Build Step

The portfolio is built as a static site using plain HTML, CSS, and JavaScript ES modules. That makes it easy to host on GitHub Pages because the repository can be served directly without bundling, compilation, or a framework-specific deployment pipeline.

HTML CSS JavaScript ES Modules GSAP Canvas 2D Three.js Dual Themes GitHub Pages

Why This Stack

Chosen for Speed, Portability, and Maintenance

  • No framework means the site stays lightweight and publishes as static files.
  • ES modules keep the code organized without requiring a bundler.
  • Theme styles are split into aurora.css and space.css, so each visual system can evolve without duplicating page content.
  • GSAP, ScrollTrigger, and Three.js are served from local files under assets/vendor/, so the deployed site is not dependent on runtime CDN access.

Runtime Flow

Boot Sequence and Main Script Responsibilities

The site uses a controller-based startup flow so each major system can initialize and clean itself up independently.

Entry Script

js/script.js

  • Acts as the browser entry point and keeps startup intentionally thin: import controllers, build them, store them, and destroy them in reverse order.
  • Waits up to 1.2s for the deferred local GSAP script to populate window.gsap before booting, so scene setup can register GSAP plugins exactly once.
  • Boots focused controllers for the active theme: Aurora loads CSS blobs, Canvas particles, GSAP scenes, and ambient UI; Space loads the Three.js background and Space-specific UI helpers.
  • Registers pagehide and beforeunload handlers that tear every controller down in reverse order for clean navigations.

Safety Net

Content Never Gets Stuck Hidden

  • An inline script in <head> adds a .js class to <html> immediately so GSAP-ready pre-hide rules can apply before first paint.
  • The same inline script sets a 1.8s fallback timer: if window.gsap never arrives, it toggles a .no-gsap class that forces every pre-hidden element back to visible.
  • This means a missing or blocked animation script can never leave the page as empty white cards.

Shared Helpers

Utility and Lifecycle Modules

  • js/modules/lifecycle.js exports createDisposer(), which tracks listeners, delegated events, timeouts, intervals, and animation frames. Controllers use the same cleanup contract to avoid leaks.
  • js/modules/utils.js contains toArray, clamp, wrapAngle, lerpAngle, prefersReducedMotion, rafThrottle, and escapeHtml.
  • Keeping these helpers in one place reduces repetition inside UI and rendering modules and makes behavior modules easier to read.

Controller Contract

Uniform Boot + Destroy Shape

  • Every controller is a factory that returns { destroy }.
  • Controllers own their own disposer instance and never leak listeners across page lifetimes.
  • Tear-down order is reverse of construction so layered effects unwind cleanly during navigation or page unload.

Interface Scripts

How the UI Layer Works

The interface logic is split into focused modules so motion, navigation, and decorative effects stay readable and maintainable.

Ambient Controller

js/modules/ambient.js

  • Handles mobile navigation open and close state, active-section highlighting via IntersectionObserver, and URL-aware menu close behavior.
  • Drives the rotating hero signal phrase, animated with a GSAP fade-swap when GSAP is available.
  • Runs the hero mouse-follow glow, panel 3D tilt with pointer light, and magnetic motion on primary + secondary buttons — all smoothed via gsap.quickTo for frame-perfect tracking.
  • Updates a --scroll-progress custom property that drives the top-edge gradient progress bar.
  • Improves contact actions by attempting Clipboard API copy first, with a toast confirmation, and falling back to the original tel: / mailto: behavior if copying fails.

GSAP Scene Director

js/modules/gsapScenes.js

  • Registers ScrollTrigger once, then orchestrates every scroll-driven and load-driven animation on the page.
  • Splits the hero h1 into per-character spans, flags the final two words with a gradient class, and plays a staggered rise on load.
  • Builds a hero intro timeline that cascades header, eyebrow, chips, subtitle, signal, body, buttons, and hero summary into place.
  • Creates ScrollTriggers for generic .reveal elements, section headings (with an underline draw hook), bullet lists, chips, key-values, metric cards, and skill-bar rows.
  • Scrubs the Experience timeline fill and each skill-bar fill directly off scroll position, so progress reads as continuous feedback instead of play-once motion.
  • Tweens metric numbers from 0 to their data-count target once on enter, with a once: true flag to keep later scrolls cheap.
  • Applies parallax to the hero content + panel and a slower drift on the dot-grid layer.
  • Runs continuous idle loops — hero chip float, summary card bob, hero glow pulse, aurora blob breath, and periodic scan-line sweep — using sine.inOut yoyo tweens.

Theme UI Helpers

futuristicUI*.js

  • Aurora keeps this layer intentionally small because most intro, reveal, and metric motion is handled by gsapScenes.js.
  • Space adds scanline card accents, count-up support, skill-bar progress, and heading glitch polish when reduced motion is not requested.
  • The older visible HUD and visitor counter have been removed from the page, so these modules no longer create those footer or top-bar displays.

Why Split the UI

Maintainability Through Boundaries

  • ambient.js handles nav, pointer glue, and content interactions.
  • gsapScenes.js owns all scroll, intro, and idle animation.
  • futuristicUI*.js handles theme-specific UI polish that is not part of the main layout.
  • Each module has a single responsibility and can be edited without reaching into the others.

Background Engine

Aurora and Space Background Systems

The merged site keeps both original visual directions. Aurora uses lightweight CSS layers and Canvas particles, while Space uses a Three.js scene with quality scaling and a static fallback for weak or blocked WebGL environments.

Aurora Controller

js/background/auroraBackground.js

  • Drives five .aurora-blob divs by writing --tx and --ty custom properties each requestAnimationFrame tick.
  • Each blob has its own Lissajous-style drift curve (phase offset, range, and speed) so the scene never visibly repeats.
  • Three of the blobs subtly weight toward the pointer, which makes the composition feel alive without any visual parallax jump.
  • Pauses cleanly on visibilitychange and falls back to a static frame under prefers-reduced-motion.
  • Shares the element transform with GSAP's idle breath tween (which animates a separate --scl property) so both systems coexist without fighting.

Particle Field

js/modules/particles.js

  • Renders 24 to 72 tiny shapes (dots, dashes, squares) drifting slowly upward on a fixed Canvas 2D context, tinted with the brand palette — blue, cyan, violet, lime, and amber.
  • Particle count scales with viewport area; opacity and density both soften on mobile.
  • Each particle has its own life cycle, rotation, and velocity, so the field looks organic without a noise texture.
  • Respects DPR up to 2x for crispness without over-drawing on high-density screens.
  • Honors prefers-reduced-motion by skipping the animation loop entirely.

Decorative Layers

Dot Grid, Scan Line, Grain, Rings

  • .dot-grid is a single masked background-image of radial dots, with a light parallax tween tied to page scroll.
  • .scan-line is a thin gradient band that GSAP sweeps down the viewport every few seconds as a soft technical signal.
  • .grain-overlay is an inline SVG feTurbulence noise tile blended at ~5% opacity for subtle texture at any resolution.
  • The hero pairs a rotating conic-gradient ring with a counter-rotating dashed ring as the hero's signature visual anchor.

Space Controller

js/background/spaceBackground.js

  • Loads Three.js only for the Space theme, then creates the scene from spaceScene.js so Aurora users do not pay for the WebGL runtime.
  • Scales quality by viewport, pointer type, DPR, and reduced-motion preference to keep mobile and desktop performance balanced.
  • Stops animation when the tab is hidden, rebuilds safely on resize and motion-preference changes, and falls back gracefully when WebGL is unavailable.
  • Art direction stays theme-local: Space CSS owns the dark layout and overlay styling, while the scene controller owns planets, starfield, ships, warp effects, and lighting.

Styling System

How the CSS Is Structured

The merged site uses separate theme stylesheets for Aurora and Space, with shared markup and JavaScript selecting the active visual system at startup.

Design Tokens

css/themes/*.css

  • Each theme file defines its own tokens in :root: surfaces, ink, accent colors, gradients, glass surfaces, shadows, radii, typography, and motion easings.
  • Theme-specific gradient tokens centralize each palette so one edit flows through the hero headline, the CTA button, section underlines, scroll progress, and metric numbers.
  • Motion timings use a cubic-bezier power3.out-style curve for the default easing, which matches the GSAP defaults in the JavaScript layer.

Section Identity

Per-Section Accent + Counters

  • Each section ID (#capabilities, #experience, #projects, #skills, #education, #contact) overrides --section-accent and --section-gradient for its subtree.
  • Eyebrow color, bullet dot gradient, heading underline gradient, and the colored contact-card icon all read those variables, so the whole section adopts its identity without extra markup.
  • A CSS counter on main increments a numbered-section counter for each .section-heading, rendered as a large translucent gradient "01" / "02" / "03" … "06" badge above each eyebrow.

Panels and Glass

Frosted Surfaces with Signature Detailing

  • Every .panel layers four thin gradient strokes (top-left coral and bottom-right violet corner brackets) over a warm-plus-cool tint wash over a translucent glass surface — drawn entirely with linear-gradient, no assets.
  • A gradient border is painted by a ::before mask trick so the border color can animate without repainting the glass behind it.
  • Pointer position and tilt angles are pushed in as custom properties from ambient.js, which keeps all 3D motion transform-only and GPU-accelerated.
  • A @supports not (backdrop-filter) block upgrades every glass surface to a stronger solid rgba so older browsers never see dim empty rectangles.

Reveals + Pre-Hide

GSAP-Ready Entry States

  • html.js-scoped rules pre-hide .reveal elements, hero content children, panels, section headings, chips, bullets, key-values, and skill bars so GSAP can animate them in without a flash-of-content.
  • A fallback rule keyed on html.no-gsap restores visibility if GSAP never loads.
  • The prefers-reduced-motion media query forces every pre-hidden element to its final state with !important, so those users always see content immediately and never see the intro cascade.

Motion and Responsiveness

Animation, Breakpoints, and Accessibility

  • Media queries at 1080 / 860 / 640 px collapse grids, swap the hero to a single column, and keep the fixed header plus mobile menu inside the viewport in portrait and landscape.
  • Hover-specific rules are scoped under @media (hover: hover) and (pointer: fine), so touch devices never get desktop-only effects.
  • Reduced-motion blocks disable idle loops, scroll-driven animations, particles, and scan line effects.

Why Split Theme Files

High Control Without a Build Tool

  • A plain CSS approach keeps the site GitHub-Pages-native — no Sass, PostCSS, or framework compilation step.
  • Custom properties provide enough flexibility for theming, section identity, and runtime tuning without a preprocessor.
  • Keeping Aurora and Space in separate files avoids a single oversized stylesheet and makes theme-specific fixes safer.

Libraries and APIs

What External Tools Are Used and Why

The project keeps outside dependencies small. Each external tool solves a clear problem.

Libraries

External Dependencies

  • GSAP 3.12.5 and ScrollTrigger are served from assets/vendor/gsap/ with defer, then consumed by gsapScenes.js. GSAP is used because it covers intro timelines, scrub-linked scroll animation, idle yoyo loops, and quickTo-smoothed pointer tracking with one coherent API.
  • Three.js 0.160.1 is dynamically imported only by the Space background controller from assets/vendor/three/, with a static fallback when WebGL cannot initialize.
  • ADLaM Display is served locally from assets/vendor/fonts/ and provides the display typeface used across every heading, paragraph, and label. The unified font is a deliberate choice to keep the site visually coherent.

Browser APIs

Native Web Features

  • IntersectionObserver — used by ambient.js for active-nav tracking and by the GSAP fallback path for reveal detection when GSAP is absent.
  • requestAnimationFrame and a small rafThrottle helper — keep aurora drift, particle stepping, and scroll-progress updates aligned with the browser's render loop.
  • matchMedia — detects prefers-reduced-motion and hover / fine-pointer capability so interactions adapt per device.
  • Clipboard API — powers the one-tap contact copy with toast confirmation.
  • Canvas 2D — drives the Aurora particle field on a single fixed canvas.
  • WebGL — powers the Space background when supported, while fallback CSS keeps the page readable without it.
  • CSS custom properties, backdrop-filter, CSS counters, and conic-gradient carry theme colors, responsive polish, and section identity.

Deployment

Why It Works Well on GitHub Pages

The project is structured so it can be uploaded as static files with minimal risk.

Hosting Notes

GitHub-Friendly Decisions

  • All local HTML, CSS, JavaScript, and asset paths are relative, so the site works from a repository subpath as well as a root domain.
  • The project includes .nojekyll, which prevents GitHub Pages from running Jekyll rules that can interfere with static asset handling.
  • The site needs no bundler, no server-side rendering, and no Node runtime — push and publish.

Operational Tradeoffs

What Is Still Loaded Externally

  • The font is served from assets/vendor/fonts/.
  • GSAP core and ScrollTrigger are served from assets/vendor/gsap/.
  • Three.js is served from assets/vendor/three/ and loaded only for the Space theme.
  • These choices keep the repository simple, while the inline no-GSAP safety net and WebGL fallback keep the page usable if an animation or rendering dependency cannot initialize.
